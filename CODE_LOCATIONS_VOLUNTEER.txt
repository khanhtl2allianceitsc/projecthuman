KEY GOTCHAS
================================================================================

1. Volunteer ID vs Member ID
   - approve(id) and reject(id) use volunteer.id from lead_volunteers.id
   - apply(projectId, memberId) and cancel() use different params

2. Status values are LOWERCASE
   - pending, approved, rejected (not Pending, Approved, Rejected)

3. ON CONFLICT upsert
   - Same project/member can re-apply
   - Line 632: resets to pending on duplicate insert

4. Previous Lead handling
   - Line 682-684: Demotes to Member (does NOT delete)
   - Only changes project_role in project_members

5. Auto-polling every 10 seconds
   - Frontend refresh() called by setInterval (line 43)

6. Deadline is UI-only
   - Server does NOT validate volunteerDeadline
   - Only UI disables apply button after deadline passes
